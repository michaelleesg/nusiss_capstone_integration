Key knobs you’ll see (and what they mean)

M (a.k.a. hnsw_m) – Max edges per node (graph connectivity).
Higher → better recall & smoother search, but more memory and slower builds.

ef_construction – Build-time breadth (how widely you search when inserting).
Higher → better index quality/recall, slower builds.

search_ef – Query-time breadth (how many candidates you explore).
Higher → higher recall, more latency (your main runtime recall knob).


HNSW (Hierarchical Navigable Small World) is a graph-based index for Approximate Nearest Neighbor (ANN) search. It organizes all vectors into multiple layers of small-world graphs: the top layers are sparse “express lanes” that let a query jump quickly across the dataset; lower layers are denser and refine to the true neighbors. Insertion links a new vector to nearby nodes while descending layers; search starts at the top, walks greedily toward closer nodes, and descends until the bottom layer, where it explores a candidate list to return top-k neighbors—much faster than brute force with high recall.
Key knobs

M (a.k.a. hnsw_m): max edges per node → higher = better recall/smoother navigation, but more memory & slower builds (we use 16).

ef_construction: build-time breadth → higher = better index quality/recall, but slower indexing (we use 128).
search_ef: query-time breadth → higher = higher recall, but more latency (we use an adaptive 64–128, ~96 default).

Why it’s good for HEVA
Scales to large CTI corpora, gives sub-linear query time, and lets us tune recall vs latency at runtime via search_ef without rebuilding the index.

neighborhood links: neighborhood.prev_chunk_id / next_chunk_id

Chunking (sentence-aware, with overlap)
Function: chunk_text(text, max_chars=1200, overlap=150)
Normalizes whitespace.
Takes windows of up to max_chars (default 1200).
Preferentially cuts at the last “. ” found before the window end; if the cut would be too short (< ~50% of max_chars), it just cuts at the window end.
Emits { "text", "start", "end" } per chunk.
Moves the cursor forward by max_chars - overlap (default overlap 150), so adjacent chunks overlap for recall.
